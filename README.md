# Cyprus bus 30 — живая карта и разметка проездов остановок

Один скрипт `bus30.py` для маршрута **30 в Лимасоле** (через `--route` подходит любой маршрут Лимасола):

- снимок всех активных автобусов в терминале;
- ближайшие прибытия на остановку;
- запись позиций в CSV;
- разметка «остановился / проехал мимо» по каждой паре «рейс × остановка» и поиск серий проездов подряд (автобус не в рейсе или переполнен);
- живая карта в браузере: остановки, автобусы, шанс того, что автобус остановится на следующей остановке. Страница обновляется каждые 30 секунд.

## Источники данных

Открытые фиды Cyprus Motion / Министерства транспорта Кипра. Ключи не нужны.

| Что | URL |
|---|---|
| Статический GTFS Лимасола: маршруты, остановки, расписание, геометрия | `https://motionbuscard.org.cy/opendata/downloadfile?file=GTFS%5C6_google_transit.zip&rel=True`, кэшируется на сутки |
| GTFS-Realtime: позиции автобусов (VehiclePosition) и прогнозы прибытия (TripUpdate) | `http://20.19.98.194:8328/Api/api/gtfs-realtime` |

Особенности фида: сам фид обновляется каждые 3–4 секунды, но позиция конкретного автобуса меняется примерно раз в 30 секунд. Скорость приходит с шагом 5 км/ч.

## Запуск

Нужен [uv](https://docs.astral.sh/uv/): он сам ставит зависимость `gtfs-realtime-bindings`. Без uv: `pip install -r requirements.txt` и `python bus30.py ...`.

```bash
uv run bus30.py                                          # все автобусы 30-го сейчас
uv run bus30.py --stop "Old Port"                        # ближайшие прибытия (stop_id или часть названия)
uv run bus30.py --watch 15 --log data/positions.csv      # обновление каждые 15 с с записью позиций в CSV
uv run bus30.py --classify data/positions.csv            # разметка проездов -> data/positions_passes.csv
uv run bus30.py --serve 8730 --log "data/positions_{date}.csv"   # карта на http://127.0.0.1:8730/
```

`{date}` в `--log` заменяется датой по Кипру, то есть пишется один файл на день. При старте сервер подгружает историю из сегодняшнего файла. Данные и кэш лежат в `data/`; другую папку можно задать переменной `BUS30_DATA_DIR`.

## Как размечаются проезды

**Одна остановка.**

- Автобус замечен в радиусе 35 м от остановки со скоростью 0 — он **стоял**.
- Иначе берутся два замера позиции по обе стороны от остановки и проецируются на линию маршрута. Время между замерами сравнивается со временем, за которое это расстояние проезжается на скорости автобуса. Настоящая остановка стоит не меньше 15 секунд (торможение, двери, разгон). Если лишнего времени почти нет, автобус **скорее проехал**.
- Медленные замеры (пробка) и большие промежутки между замерами сдвигают оценку к 50/50 (**неясно**).

**Несколько остановок подряд.** Рейс проходит через скрытую марковскую цепь с двумя режимами:

- «в рейсе»: пропускает остановку, только если там никто не ждёт, доля задаётся `--base-pass-rate` (по умолчанию 0,3 — это допущение, его стоит откалибровать на данных);
- «едет мимо»: не в рейсе или полный, пропускает около 95% остановок.

Режим меняется редко (`--switch` 0,1), поэтому вероятные проезды подряд складываются. Пять проездов с уверенностью около 80% дают примерно 80% на режим «едет мимо». Одно замеченное стояние на остановке почти обнуляет эту версию. Серия попадает в отчёт, если в ней не меньше `--min-run` (3) остановок с P(«едет мимо») ≥ `--skip-threshold` (0,8).

Отличить «не в рейсе» от «переполнен» по одним координатам нельзя. Скрипт даёт только подсказку: серия на весь наблюдённый рейс — скорее «не в рейсе», серия на части рейса — скорее «полный».

**Шанс остановки на карте** — прогноз для следующей остановки: (1 − P(«едет мимо»)) × (1 − base_pass_rate) + P(«едет мимо») × 0,05. У обычного автобуса в рейсе это около 64%.

## Деплой (systemd + nginx с логином и паролем)

```bash
useradd --system --home /opt/cyprus-bus --shell /usr/sbin/nologin bus30
git clone https://github.com/DarkPatrick/cyprus-bus /opt/cyprus-bus   # или скопировать файлы
python3 -m venv /opt/cyprus-bus/.venv && /opt/cyprus-bus/.venv/bin/pip install -r /opt/cyprus-bus/requirements.txt
mkdir -p /opt/cyprus-bus/data && chown -R bus30: /opt/cyprus-bus/data
cp /opt/cyprus-bus/deploy/bus30.service /etc/systemd/system/ && systemctl enable --now bus30
```

Сервис слушает только `127.0.0.1:8093`. Наружу его отдаёт nginx: сниппет `deploy/nginx-location.conf` добавляется в существующий HTTPS-блок `server { }`, логин и пароль хранятся в `/etc/nginx/bus30.htpasswd`. Затем `nginx -t && systemctl reload nginx`.
